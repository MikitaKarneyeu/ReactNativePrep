Edge deployment runs AI models directly on end-user devices (phones, tablets, IoT devices, embedded systems) rather than in the cloud. The model is optimized for the target hardware and runs inference locally, processing data on the device without sending it to external servers.

Edge deployment is driven by requirements that cloud deployment cannot meet. Latency-critical applications (autonomous vehicles, real-time AR, industrial control) cannot tolerate network round-trip delays. Privacy-sensitive applications (health monitoring, personal assistants) benefit from data never leaving the device. Offline-capable applications (navigation, translation) must work without network connectivity. Cost-sensitive applications at massive scale benefit from eliminating per-inference server costs.

The technical challenges include limited compute (mobile CPUs/GPUs are much less powerful than server hardware), memory constraints (models must fit in device RAM), power consumption (inference must not drain battery), and model update logistics (distributing updated models to millions of devices). Model optimization is essential—quantization (float32 to int8), pruning, knowledge distillation, and architecture optimization (MobileNet, EfficientNet-Lite for vision; DistilBERT, TinyBERT for NLP).

Deployment frameworks include Core ML (Apple ecosystem), TensorFlow Lite (Android, embedded), ONNX Runtime Mobile (cross-platform), and MediaPipe (real-time vision pipelines). These frameworks handle model conversion, optimization, and hardware acceleration (leveraging NPUs, GPUs, and DSPs on the device). Models can be bundled with the app, downloaded on-demand, or updated over-the-air.

Use cases include: real-time camera features (filters, object detection, OCR), voice recognition and NLP (on-device assistants, text prediction), health monitoring (activity recognition, vital sign analysis), and industrial IoT (predictive maintenance, quality inspection on factory floors). The trend is toward larger, more capable on-device models as mobile hardware improves. Hybrid approaches use on-device models for real-time features and cloud models for complex tasks—sending requests to the cloud only when needed.
