The context window is the maximum amount of text an LLM can process in a single input—the total number of tokens the model can "see" at once. This includes the system prompt, conversation history, user query, and any retrieved context. Context window sizes vary dramatically: GPT-3.5 has 4K tokens, GPT-4 supports 8K-128K tokens, Claude supports up to 200K tokens, and some models support 1M+ tokens.

Context window size directly impacts what you can build. A 4K context window fits roughly 3,000 words—enough for a short conversation but insufficient for analyzing long documents. A 128K window fits a full book, enabling document summarization, analysis of lengthy codebases, and extended conversations. Larger context windows enable RAG with more retrieved passages, longer conversation histories, and processing of complex multi-document inputs.

The technical challenge is that self-attention has quadratic complexity O(n²) with sequence length—a 10x longer context requires 100x more computation and memory. This makes long context windows expensive. Efficient attention mechanisms (Flash Attention, sliding window attention, sparse attention) reduce this cost. Some models use a sliding window approach, attending only to recent tokens plus summarized older context.

Practical considerations include that models often struggle to use information in the middle of long contexts ("lost in the middle" problem)—they attend more to the beginning and end. Placing important information at the start or end of the context improves retrieval. Token costs are proportional to context length—processing 100K tokens is much more expensive than 1K tokens. In practice, use the smallest context window that fits your use case to minimize cost and latency. Structure prompts so the most critical information is at the beginning, and use RAG to retrieve only relevant passages rather than dumping entire documents into context.
