Vector databases are specialized data stores designed to efficiently store, index, and query high-dimensional vector embeddings. Unlike traditional databases that index scalar values (numbers, strings) using B-trees or hash indexes, vector databases index dense vectors using algorithms optimized for similarity search in high-dimensional spaces. They enable finding the "nearest neighbors" to a query vector—vectors that are semantically similar.

They are needed because traditional databases cannot efficiently perform similarity search on embeddings. A naive approach would compute the distance between the query vector and every stored vector (brute force), but this is O(n) and too slow for millions or billions of vectors. Vector databases use approximate nearest neighbor (ANN) algorithms like HNSW (Hierarchical Navigable Small World), IVF (Inverted File Index), or Product Quantization to find similar vectors in milliseconds, trading a small amount of accuracy for massive speed improvements.

The rise of embeddings in modern AI applications drives demand for vector databases. Embedding models convert text, images, audio, and other data into dense vectors that capture semantic meaning. These embeddings enable semantic search (finding documents by meaning, not keywords), recommendation systems (finding similar items), and RAG (retrieving relevant context for LLMs). Storing and querying these embeddings at scale requires a vector database.

Key features include: vector storage and indexing with sub-linear query times, metadata filtering (combining vector search with traditional filters like date or category), CRUD operations (insert, update, delete vectors), and scalability (handling billions of vectors across distributed nodes). Vector databases typically support distance metrics like cosine similarity, Euclidean distance, and dot product. They can be standalone services (Pinecone, Weaviate, Milvus) or extensions to existing databases (pgvector for PostgreSQL, Redis with vector search, Elasticsearch with dense vectors). The choice depends on scale, existing infrastructure, and specific feature requirements.
