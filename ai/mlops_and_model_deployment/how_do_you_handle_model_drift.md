Model drift occurs when a deployed model's performance degrades over time because the data it sees in production differs from the data it was trained on. This is inevitable—the world changes, user behavior evolves, and the relationships the model learned become less accurate. There are two types: data drift (input distribution changes) and concept drift (the relationship between inputs and outputs changes).

Data drift happens when the distribution of input features shifts. For example, a model trained on pre-pandemic data may see very different user behavior during and after a pandemic. A recommendation model trained on summer data may perform poorly in winter. Statistical tests detect data drift by comparing production data distributions to training data distributions. The Kolmogorov-Smirnov test, Population Stability Index (PSI), and chi-squared test are commonly used.

Concept drift happens when the relationship between inputs and outputs changes. A fraud detection model may become less effective as fraudsters change their tactics. A sentiment model may misclassify new slang or cultural references. Concept drift is harder to detect because you need ground truth labels to measure prediction accuracy. Monitor prediction quality metrics over time—if accuracy drops while input distributions remain stable, concept drift is likely.

Handling drift involves monitoring, detection, and response. Monitor data distributions and prediction quality continuously. Set thresholds for acceptable drift and alert when exceeded. Implement automated retraining pipelines that trigger when drift is detected. Use the most recent production data (with ground truth labels) to retrain the model. Some systems implement continuous training—regularly retraining on the latest data regardless of detected drift.

Proactive strategies include: training on diverse data that covers expected distribution shifts, using online learning (updating the model incrementally as new data arrives), implementing champion-challenger frameworks (always testing new model versions against the current production model), and designing models that are robust to distribution shifts (domain adaptation techniques). For LLM applications, drift can occur in user queries, expected response formats, or knowledge requirements—monitor query distributions and response quality metrics continuously.
