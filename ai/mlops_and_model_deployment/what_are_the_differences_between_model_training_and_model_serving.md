Model training and model serving are fundamentally different phases with different requirements, infrastructure, and optimization strategies. Training is the process of learning patterns from data—it's computationally intensive, offline, and optimized for throughput. Serving is the process of using the trained model to make predictions—it's latency-sensitive, online, and optimized for response time.

Training requires large amounts of compute (GPUs/TPUs), extensive memory for data and gradients, batch processing for efficiency, and can run for hours to days. The focus is on convergence (reaching good performance) and throughput (processing as much data as possible). Distributed training across multiple machines is common for large models. Training frameworks include PyTorch, TensorFlow, and JAX.

Serving requires low latency (milliseconds to seconds), high availability (always online), efficient resource usage (cost-effective at scale), and handling concurrent requests. The focus is on inference speed, not learning. Optimization techniques include model quantization (reducing precision from float32 to int8), model pruning (removing unnecessary weights), model distillation (training a smaller model to mimic the larger one), and batching requests for GPU efficiency.

Infrastructure differences: training uses ephemeral clusters that scale up for training jobs and shut down after. Serving uses persistent infrastructure with auto-scaling to handle traffic variations. Training data is stored in data lakes or warehouses. Serving receives data via API requests. Training experiments are tracked in experiment management systems. Serving monitors latency, error rates, and throughput.

Serving architectures include: REST APIs (standard HTTP endpoints), gRPC (lower latency, better for internal services), batch inference (processing large datasets offline), and streaming (real-time predictions on data streams). Model serving frameworks include TensorFlow Serving, TorchServe, Triton Inference Server (NVIDIA), and cloud services (AWS SageMaker Endpoints, Google Vertex AI Prediction). For LLMs, specialized serving frameworks like vLLM, TGI (Text Generation Inference), and TensorRT-LLM optimize for the unique characteristics of autoregressive generation.
