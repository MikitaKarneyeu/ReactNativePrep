Retrieval-Augmented Generation (RAG) is a technique that enhances LLM responses by retrieving relevant information from external knowledge sources and including it in the prompt. Instead of relying solely on the model's parametric knowledge (learned during training), RAG provides access to current, domain-specific, or proprietary information at inference time. This addresses hallucinations, knowledge cutoffs, and the inability to access private data.

A RAG pipeline has three main components. The indexing phase processes documents into searchable chunks: documents are split into passages, each passage is converted into an embedding vector using an embedding model, and these vectors are stored in a vector database. The retrieval phase, given a user query, converts it to an embedding, performs similarity search against the vector database, and retrieves the most relevant passages. The generation phase combines the retrieved context with the user's query in a prompt and sends it to the LLM to generate a response.

RAG provides several advantages over fine-tuning. It's easier to update—adding new documents just requires re-indexing, not retraining. It provides citations and sources, improving trustworthiness. It keeps the LLM's general capabilities intact while adding domain knowledge. It's more cost-effective than fine-tuning for frequently changing knowledge bases.

Best practices include using hybrid search (combining semantic search with keyword search), re-ranking retrieved passages by relevance, using overlapping chunks to avoid splitting relevant information, and including metadata (source, date, section) in chunks. Advanced techniques include multi-step retrieval (querying multiple times), query expansion (generating multiple query variations), and self-RAG (the model decides when to retrieve). In practice, RAG is the standard approach for building LLM applications that need access to specific knowledge—customer support, documentation search, internal knowledge bases, and research assistants.
