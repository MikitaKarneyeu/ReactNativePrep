Prompt engineering is the practice of designing inputs to LLMs to elicit desired outputs without changing the model's weights. Since LLMs are conditioned on their input, the way you phrase a question or structure a prompt dramatically affects output quality. Key techniques include zero-shot prompting (asking directly without examples), few-shot prompting (providing examples in the prompt), and chain-of-thought prompting (asking the model to reason step-by-step).

Zero-shot prompting works for straightforward tasks: "Translate the following English text to French:" followed by the text. For more complex or ambiguous tasks, few-shot prompting provides examples that demonstrate the expected input-output format. The examples should be diverse, representative, and cover edge cases. The number of examples depends on task complexity—typically 3-5 is sufficient.

Chain-of-thought (CoT) prompting asks the model to explain its reasoning before giving the final answer: "Let's think step by step." This significantly improves performance on math, logic, and multi-step reasoning tasks. Self-consistency generates multiple reasoning paths and selects the most common answer. Tree-of-thought explores multiple reasoning branches and evaluates them.

Structured prompting techniques include role prompting ("You are an expert Python developer..."), which sets context and expertise level. Output formatting instructions ("Respond in JSON with keys: summary, confidence, sources") ensure parseable outputs. Constraint specification ("The answer must be under 100 words" or "Only use these categories: positive, negative, neutral") controls output characteristics. System messages establish persistent behavior, while user messages contain the specific request.

Advanced techniques include prompt chaining (breaking complex tasks into sequential prompts), where the output of one prompt becomes input for the next. Retrieval-augmented generation (RAG) enriches prompts with relevant context from external sources. Meta-prompting uses LLMs to generate or optimize prompts. In practice, prompt engineering is iterative—test variations, evaluate outputs, and refine based on results. What works for one model may not work for another, so prompts should be validated across target models.
