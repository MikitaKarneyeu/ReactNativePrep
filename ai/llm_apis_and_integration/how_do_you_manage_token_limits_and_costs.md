Token management is critical for LLM applications because costs are directly proportional to token usage and context window limits constrain what you can include in prompts. Tokens are the basic units of text processing—roughly 4 characters or 0.75 words in English. A 1000-word document is approximately 1,300 tokens. Input tokens (prompt) and output tokens (completion) are typically priced differently, with output tokens costing 2-4x more.

Count tokens before sending requests to avoid exceeding context limits and unexpected costs. Use the tokenizer from the model's provider (tiktoken for OpenAI, Anthropic's tokenizer) to count tokens precisely. Implement pre-flight checks: if the prompt + expected output exceeds the model's context window, truncate or summarize the input. For conversation history, implement sliding windows (keeping the most recent N messages) or summarization (compressing older messages into a summary).

Cost optimization strategies include choosing the right model for each task—use GPT-3.5-turbo for simple tasks and reserve GPT-4 for complex reasoning. Implement caching for repeated or similar queries—exact match caching with Redis, or semantic caching using embeddings to find similar past queries. Compress prompts by removing unnecessary formatting, using shorter system prompts, and summarizing retrieved context before including it in the prompt.

Implement usage tracking and budgets. Log every API call with token counts and costs. Set per-user or per-application budgets with alerts when approaching limits. Use token counting in your application logic to estimate costs before making requests. Implement request deduplication—don't make identical requests multiple times. For batch processing, group related requests to minimize system prompt overhead. Monitor your token distribution to identify optimization opportunities—often 80% of tokens come from 20% of features, which are the best targets for optimization.
