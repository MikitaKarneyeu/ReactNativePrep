The training set is the largest portion of data (typically 60-80%) used to fit the model. The model learns patterns, adjusts weights, and optimizes parameters based on this data. The training set directly influences the model—every gradient update, every split in a decision tree, every learned representation comes from training data. Quality and representativeness of training data is the single most important factor in model performance.

The validation set (typically 10-20%) is used for hyperparameter tuning, model selection, and monitoring during training. It is not directly used for gradient updates but influences decisions about the model: which hyperparameters to choose, when to stop training (early stopping), which architecture performs best, and which features to include. The validation set acts as a proxy for unseen data during development. Common approaches include hold-out validation, k-fold cross-validation, and stratified splits.

The test set (typically 10-20%) is held out completely until the final evaluation. It provides an unbiased estimate of how the model will perform on truly unseen data. The test set should never influence any decision during model development—no hyperparameter tuning, no feature selection, no early stopping decisions based on test performance. Using test data for any development decision leads to information leakage and overly optimistic performance estimates.

In practice, the split ratios depend on dataset size. For very large datasets (millions of samples), a 98/1/1 split works fine because even 1% provides statistically reliable estimates. For small datasets, cross-validation is preferred over a single split. Time-series data must be split chronologically—future data cannot appear in training. Some domains use additional splits: a calibration set for probability calibration, or a deployment set for A/B testing. The key principle is that each set serves a distinct purpose, and using test data for anything other than final evaluation invalidates your performance claims.
