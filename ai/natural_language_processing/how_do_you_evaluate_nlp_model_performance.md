Evaluating NLP model performance requires task-specific metrics, as different tasks have different notions of correctness. For classification tasks (sentiment analysis, spam detection), standard metrics include accuracy (overall correctness), precision (how many predicted positives are correct), recall (how many actual positives are found), and F1-score (harmonic mean of precision and recall). For imbalanced datasets, accuracy can be misleading—F1 and area under the ROC curve (AUC-ROC) are more informative.

For generation tasks (summarization, translation, text generation), automatic metrics include BLEU (comparing n-gram overlap with reference translations), ROUGE (measuring recall of reference content in summaries), and METEOR (considering synonyms and paraphrases). Perplexity measures how well a language model predicts text—lower perplexity indicates better predictions. However, automatic metrics often correlate poorly with human judgment for open-ended generation.

Modern evaluation increasingly uses LLM-as-a-judge, where a strong model evaluates outputs from other models on criteria like helpfulness, accuracy, and safety. Benchmarks like MMLU (massive multitask language understanding), HumanEval (code generation), and MT-Bench (multi-turn conversation) provide standardized evaluation. Human evaluation remains the gold standard—having humans rate outputs on relevance, coherence, fluency, and factual accuracy.

For production systems, evaluation extends beyond offline metrics. A/B testing measures real user engagement and satisfaction. Task completion rates measure whether users achieve their goals. Latency and throughput matter for user experience. Factual accuracy and hallucination rates are critical for knowledge-intensive applications. In practice, a combination of automatic metrics, human evaluation, and production metrics provides the most complete picture of model performance. Evaluation should be continuous—models can degrade over time as user behavior and data distributions change.
